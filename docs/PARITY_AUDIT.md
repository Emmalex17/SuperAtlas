## The 10 biggest gaps

1. **The organisation-side "Compliance" tabbed surface doesn't exist (P9, 0/15 matches — worst phase).** `org/compliance`, `org/compliance/programme`, and `org/exposure` have no routes at all; only a standalone, untabbed `/organisation/actions` page exists. The prototype's `compStatus()`/`compChip()` and exposure-level (High/Medium/Low) calculations have no equivalent anywhere in `src/lib` — confirmed by repo-wide grep.
2. **Assessors can't see what organisations actually submitted (P6, 0/11 matches — tied worst phase).** `firm/assess` only has 2 of 5 tabs; the Requirements tab jumps straight from the requirement text to the outcome picker with no "organisation's answers" section, no divergence warnings, no "Ask" button. `org/assessment` (the org-side counterpart: information requests, interviews, outcome preview) doesn't exist anywhere.
3. **Organisations and firms have no self-service workspace (P3, 9/32 matches).** `org/welcome`, `org/team`, `org/profile` (all 5 tabs), `firm/welcome`, `firm/team`, `firm/profile` (all 5 tabs) are entirely missing. Orgs/firms can only be viewed/managed from the regulator side.
4. **The entire regulator Settings section is missing (P2, 2/24 matches).** No `settings/*` routes, no "Settings" nav entry at all. Oddly, typed data for several of these screens already exists (`schemes.json`, `deadlines.json`, `findingClasses.json`, `compliance.json`, `actionTypes.json`) but is completely unimported — an orphaned data layer with no UI.
5. **Firms have no way to verify organisation-submitted fixes (P7).** `firm/findings` and `firm/finding` don't exist anywhere — confirmed via repo-wide grep for "Fixes to verify"/"Being fixed"/"Verified and closed", zero hits. This breaks the findings-remediation loop (org submits fix → firm verifies → regulator closes).
6. **The app shell is a simplified rewrite, not a port (P10).** The sidebar drops all section groupings, live count badges, Help, and Settings; the top bar has no real per-page breadcrumbs, no Ctrl/⌘K command palette (zero matches anywhere in `src/`), no tasks button, and the bell/user menu are plain links instead of popovers. There's no idle-timeout warning dialog at all.
7. **No programme-creation path and no programme analytics (P5).** `programmes/new`'s 6-step wizard doesn't exist — both "New programme" and "Continue setup" buttons are dead. `programmes/view`'s Analytics tab (cycle/category selectors, 7 stat cards, submission-by-category chart) is entirely absent from the tab list.
8. **No requirement/regulation authoring surface exists (P4).** `library/requirement`, `library/edit`, `library/ai` are all missing; the regulation page's "Actions" card (Edit/Add requirement/New version/Publish) is gone; all three action buttons on the library list ("Add regulation", "Import spreadsheet", "Add with AI") are dead.
9. **The invitation accept-flow is missing, and sign-in still links where it shouldn't (P1).** `invitation`, `invitation/zenith`, `invitation/deloitte` have no routes — there is no way to onboard a new regulator/org/firm admin through an invite. Separately, `signin` still links to `/register`, which violates the agreed "kept in code but unlinked from anywhere" rule.
10. **Data returns: no Insights tab, no template builder (P8).** `returns`' tab bar has 3 of the prototype's 4 tabs (Insights is gone, content and all). `returns/template` (the return-template builder: Basics, Fields table, Publish) doesn't exist, and its launch buttons are either dead or mis-wired to open the wrong dialog.

Chart-kit/KPI primitives are also mostly unported (`chBars`, `chStack`, `chFunnel`, `chHeat`, `chDots`, `kTile`, `chCard`'s "View as table" toggle all missing from `src/lib/charts.ts`) — closely tied to gap #6 and #7, since it blocks faithful rebuilds of every dashboard/analytics screen.

One correction to the brief's own premise: **the favicon/app icons are not missing.** `src/app/icon.tsx` and `apple-icon.tsx` already generate the branded mark (landed in the "Polish pass" commit `86feda6`). Treat that agreed-difference item as done.

### Questions
- The prototype's sign-in screen includes SSO options (Continue with Google, Continue with Microsoft, Single sign-on/SAML) via `ssoBtns()` in `auth.js`, but the app's `signin/page.tsx` has no SSO UI at all. Is SSO explicitly descoped for the pilot, or is this a genuine gap that should be tracked separately (it wasn't listed in PARITY_INVENTORY.md's P1 "Buttons and links" for `signin`, so the inventory itself may already treat SSO as out of scope — worth confirming before rebuilding).
- The signin page's "Register your organisation" link to `/register` appears to be a leftover that should be removed per the agreed-difference note ("unlinked from anywhere"). Flagging rather than fixing, per the read-only audit instruction.
- The three `invitation*` routes are entirely missing, including the underlying accept-invitation → set-password → MFA-setup flow. Given P1 is "Public site and sign-in," and invitations are how new regulator/organisation/firm admins actually get onboarded in the prototype, this seems like a significant omission rather than a cosmetic one — worth confirming whether the pilot intentionally onboards everyone through demo accounts only (no real invitation flow), which would make this an intentional scope cut rather than a gap, but it isn't listed among the "Known AGREED deliberate differences" in the task brief.

### Questions

- Should the "Settings" left-nav shell (`settingsShell`/`SETTINGS_NAV`) be built as a standalone layout component shared by `profile`, `profile/branding`, `team`, and the 7 `settings/*` screens, matching the prototype's Slack/ClickUp-style pattern? This affects the architecture of 4+ already-built screens (profile, branding, team, and their tab states) as well as all 7 missing settings screens, so it's worth deciding before any rebuild starts rather than treating each screen as independent.
- The `settings/*` data already exists as typed JSON (`src/lib/data/schemes.json`, `deadlines.json`, `findingClasses.json`, `compliance.json`, `actionTypes.json`) but is completely unused. Was this data layer built in anticipation of these screens, or is it leftover/unrelated? Worth confirming before building the UI on top of it.
- Is the `organisations/invite` "Spreadsheet" bulk-invite mode considered in-scope for the rebuild, or was leaving it out of the current single-form implementation a deliberate scope cut? Given its size (upload, processing, row-conflict resolution), it's worth flagging explicitly rather than assuming it's a straightforward addition.
- Should AppShell's breadcrumb (`<b>{account.entityName}</b>`, static on every screen) be replaced with real per-page breadcrumbs (e.g. "Profile > Details", "Settings > Categories")? This is a cross-cutting gap affecting every P2 screen (and likely every screen in the app), not unique to P2, so it may be better tracked as one global fix rather than per-screen.
